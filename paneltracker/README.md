# Panel Tracker

Локальная Windows-программа (WPF, .NET 10) для отслеживания статусов чертежей сборных ж/б панелей.
Без сервера и без базы данных: **статус панели равен папке, в которой лежит её PDF**. Программа только
показывает доску, считает статистику и перемещает файлы между папками статусов; всё остальное — обычные папки,
с которыми можно работать и в проводнике.

## Принцип работы

```
D:\Projects\Tower-A\Panels\          ← корневая папка проекта (выбирается в программе)
├── 01 Ready to Check\               ← папка статуса «Готово к проверке»
│   ├── N021.pdf                     ← имя файла без расширения = идентификатор панели
│   └── W046_R2.pdf                  ← суффикс ревизии: актуальной считается старшая
├── 02 Ready to Back Check\
├── 03 Ready to Send\
├── 04 Sent to client\               ← роль sent: учитывается в полосе прогресса
├── 05 Problem\                      ← роль problem: команда «Отметить „Проблема“»
├── 06 Locked\                       ← роль hold: команды «Заблокировать / Снять блокировку»
├── groups.json                      ← группы панелей (создаётся программой)
└── history.jsonl                    ← журнал переходов статусов (создаётся программой)
```

* Перетащили файл в другую папку в проводнике — доска обновится сама (FileSystemWatcher + периодический
  пересчёт раз в 10 с), а в историю попадёт запись «Обнаружено (вне программы)».
* Перевели панель в статус из контекстного меню — файл физически переместился в папку статуса, запись в историю с именем
  пользователя Windows.
* Файлы одной панели в двух и более папках статусов — **дубликат**: плитка помечена «⚠», список на вкладке «Дубликаты».
* Ревизии: `N021.pdf`, `N021_R1.pdf`, `N021_R2.pdf` — одна панель `N021`, актуален `N021_R2.pdf`, на плитке «R2».
  Поддерживаются суффиксы `_R2`, `-R2`, ` R2`, `_rev2`, `_Rev.2`, ` (R2)`.
* Группы (A: Solid panel, B: Spandrel, C: HM door panel, D: Corner panel — по умолчанию) хранятся в `groups.json`,
  ключ группы показывается в углу плитки, доску можно фильтровать по группе.

## Интерфейс

| Область | Что делает |
|---|---|
| Верхняя панель | Выбор папки проекта, «Создать папки статусов», «Открыть папку», «Обновить» (F5) |
| Счётчики | Всего панелей; по каждому статусу — количество и процент (щелчок = фильтр по статусу); дубликаты; полоса «Отправлено заказчику N из M» |
| Доска | Плитка на панель в цвете статуса; поиск по тексту, фильтры по статусу и группе; выделение Ctrl/Shift, Ctrl+A; двойной щелчок открывает PDF |
| Контекстное меню плитки | Открыть файл · Открыть расположение · Перевести в статус… · Заблокировать (HOLD) · Снять блокировку · Отметить «Проблема»… · Добавить в группу · Убрать из группы — для всех выделенных плиток |
| Дубликаты | Таблица файлов панелей, лежащих в нескольких папках, с кнопкой «Открыть расположение» |
| История | Журнал `history.jsonl`: когда, кто, панель, файл, откуда, куда, действие, комментарий; фильтр по панели |
| Группы | Добавить / переименовать / удалить группу; состав группы; добавление выделенных на доске панелей |
| Статистика | Сводная таблица «группа × статус»: сколько панелей каждой группы в каждом статусе, всего и отправлено |
| Настройки | Путь к `settings.json`, кнопки «Открыть settings.json» и «Перечитать настройки», таблица статусов |

## Конфигурация: `settings.json`

Файл лежит рядом с `PanelTracker.exe` и создаётся со значениями по умолчанию при первом запуске.
Пример — [docs/settings.example.json](docs/settings.example.json).

| Поле | Значение по умолчанию | Назначение |
|---|---|---|
| `rootFolder` | — | Корневая папка проекта; запоминается при выборе в программе |
| `fileExtensions` | `[".pdf"]` | Какие файлы считать чертежами |
| `includeSubfolders` | `false` | Искать файлы и во вложенных папках внутри папок статусов |
| `rescanIntervalSeconds` | `10` | Период принудительного пересканирования |
| `debounceMilliseconds` | `600` | Пауза после последнего события файловой системы перед пересканированием |
| `userName` | — | Имя для журнала; пусто — имя учётной записи Windows |
| `statuses[]` | 6 статусов | Порядок в списке = порядок на доске и в меню |

Поля статуса: `key` (латиницей, попадает в историю), `name` (подпись в интерфейсе), `folder` (имя подпапки),
`color` (`#RRGGBB`), `role` — `normal`, `sent` (учитывается в прогрессе «отправлено»), `problem` (куда попадает панель
по команде «Проблема»), `hold` (куда попадает по команде «Заблокировать»). Ролей `problem` и `hold` может не быть —
тогда соответствующие команды сообщат об этом.

После правки файла нажмите «Перечитать настройки» на вкладке «Настройки» или перезапустите программу.
Если `PanelTracker.exe` лежит в папке без прав на запись (например, `Program Files`), скопируйте его в другую папку —
`settings.json` должен быть доступен для записи.

### `groups.json`

```json
{ "groups": [ { "key": "A", "name": "Solid panel", "panels": ["N021", "N022"] } ] }
```

### `history.jsonl`

Одна JSON-строка на событие:

```json
{"timestamp":"2026-10-18T12:34:56+03:00","user":"ivanov","machine":"PC-07","panelId":"N021","fileName":"N021_R2.pdf","fromStatus":"ready_to_check","toStatus":"sent","action":"moved"}
```

`action`: `moved`, `held`, `released`, `problemMarked` (с полем `comment`), `detected` (перемещение вне программы,
`user` = «проводник»).

## Структура решения

```
paneltracker/
├── PanelTracker.sln
├── src/PanelTracker.Core/          логика: настройки, сканер, ревизии, группы, история, операции, наблюдатель (без WPF)
├── src/PanelTracker.App/           WPF-приложение (MVVM, CommunityToolkit.Mvvm)
├── tests/PanelTracker.Core.Tests/  xUnit-тесты ядра на временных каталогах (проходят на macOS/Linux/Windows)
└── docs/                           settings.example.json, windows-verification.md
```

Решение самостоятельное: `Directory.Build.props` и `Directory.Packages.props` в этой папке не наследуют настройки
DrawingFlow из корня репозитория. Сборка идёт с `TreatWarningsAsErrors`.

## Запуск на Windows

Нужен [.NET SDK 10](https://dotnet.microsoft.com/download/dotnet/10.0) (для `dotnet run`) — либо только готовый exe (см. ниже).

```bash
cd paneltracker
dotnet run --project src/PanelTracker.App
```

Тесты ядра (на любой ОС):

```bash
dotnet test paneltracker/PanelTracker.sln
```

### Сборка одним exe

Самодостаточный exe (~130 МБ, .NET на целевой машине не нужен); параметры `SelfContained`, `PublishSingleFile`
уже заданы в проекте:

```bash
dotnet publish paneltracker/src/PanelTracker.App -c Release -r win-x64 -o paneltracker/publish/win-x64
```

Результат — `paneltracker/publish/win-x64/PanelTracker.exe`. Скопируйте его в любую папку с правами на запись и запустите;
рядом появится `settings.json`.

Вариант поменьше (~1 МБ), требует установленного
[.NET Desktop Runtime 10 x64](https://dotnet.microsoft.com/download/dotnet/10.0):

```bash
dotnet publish paneltracker/src/PanelTracker.App -c Release -r win-x64 --self-contained false -o paneltracker/publish/win-x64-fdd
```

Обе команды выполняются и на macOS/Linux (в проекте включён `EnableWindowsTargeting`), но запустить WPF-программу
можно только на Windows. Список ручных проверок — [docs/windows-verification.md](docs/windows-verification.md).

## Ограничения текущей версии

* Один пользователь, одна машина; при работе нескольких человек с общей сетевой папкой доска у каждого обновится,
  но `history.jsonl` и `groups.json` пишутся без блокировок.
* Нет сравнения ревизий чертежей и интеграции с Tekla — это отдельные задачи.
* Перемещается только актуальный файл панели (старшая ревизия); старые ревизии остаются на месте.
