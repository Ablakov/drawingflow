## Этап 1 — что сделано

* Решение из 10 проектов; сборка без ошибок и предупреждений (включая WPF на macOS через `EnableWindowsTargeting`).
* Сервер: JWT + refresh-токены с ротацией, роли и права (вычисляются на сервере), организации/проекты/участники, пользователи сервера, аудит, health-checks, ProblemDetails на русском, ограничение частоты входа, первичная инициализация администратора, явные миграции.
* Desktop: вход с выбором сервера, главное окно с навигацией и строкой состояния, страницы проектов (поиск/сортировка/пагинация на сервере), проекта, участников, аудита, администрирования, настроек; диалоги создания/изменения; состояния загрузки/пустоты/ошибки/разрыва связи; сессия в DPAPI.
* Клиентская библиотека с упреждающим продлением токена и повтором запроса после 401.
* Тесты: 86 модульных и 36 интеграционных (реальный PostgreSQL): изоляция организаций, IDOR, матрица ролей, уникальность под конкурентной нагрузкой, ротация токенов, блокировки, ограничение частоты, аудит.

## Этап 2 — что сделано

* Домен: `Document`, `DocumentVersion`, таблица переходов `DocumentWorkflow`; новая версия всегда возвращает документ в «В работе»; архив блокирует загрузку.
* Хранилище: `IFileStorage` + `FileSystemStorage` (временный файл → атомарное перемещение, SHA-256 и размер при приёме, лимит размера, проверка ключей, запрет выхода за корень, неизменяемость объектов).
* Сервер: реестр документов (поиск/фильтры/сортировка/пагинация), регистрация, изменение метаданных с оптимистичной блокировкой, архив/восстановление,
  потоковая загрузка версий с идемпотентностью и выдачей номеров под блокировкой строки, скачивание с проверкой прав, недавние документы организации, аудит всех операций, 503 при отказе хранилища.
* Клиент: потоковые загрузка и скачивание с прогрессом, без ограничения по времени (обычные запросы — с тайм-аутом).
* Desktop: страницы «Документы» и «Документ», диалоги регистрации/изменения, загрузки версии (локальный SHA-256, прогресс, один ключ идемпотентности на попытку) и сравнения версий;
  открытие версии в связанном приложении и показ в Проводнике через проверенную локальную копию; недавние документы на главной.
* Тесты: 134 модульных и 50 интеграционных, в т. ч. 6 параллельных загрузок в один документ, идемпотентный повтор, несовпадение SHA-256, превышение лимита, архив, конфликт версий записи, отказ хранилища (нет записи / отсутствует объект).

## Этап 3 — что сделано

* Сервер: агенты (регистрация с одноразовым ключом, отзыв с немедленным действием, сердцебиение), папки наблюдения, серверная очередь операций с действиями пользователей, поиск документов для сопоставления, ограничение прав агента проектами его папок, аудит.
* Агент: служба Windows с CLI `register`/`status`; защищённое хранение ключа; очередь SQLite (операции, состояния файлов, кэш конфигурации); наблюдатель с дебаунсом + периодическая сверка;
  стабильность файла; SHA-256; сопоставление по правилам папки; автоматическая регистрация по настройке; идемпотентная загрузка; экспоненциальные повторы с пределом; восстановление после перезапуска; приостановка при отзыве.
* Клиент: `AgentTokenHandler`, методы агента и администрирования.
* Desktop: страницы «Агенты» (регистрация, ключ, отзыв, папки) и «Синхронизация» (операции, повтор, сопоставление, отклонение), сводка на главной.
* Тесты: 163 модульных и 67 интеграционных; конвейер агента проверен сквозными сценариями (ровно одна версия, изменение/касание, дубликаты событий, разрешение пользователем,
  автоматическая регистрация, заблокированный файл, перезапуск, обрыв сети и ограниченные повторы, отзыв ключа, недоступная папка, удалённый файл, временные файлы).

## Этап 4 — что сделано

* Домен: `Review` (решение по версии), `WorkflowTask` (проверка/доработка), команды документа `SubmitForReview`, `Approve`, `RequestRevision` (комментарий обязателен), `Release`;
  вытеснение непроверенной версии (`Superseded`) при загрузке новой, сохранение статусов согласованных и выпущенных версий.
* Сервер: `WorkflowService` — отправка на проверку с назначением проверяющих и сроком, решения (назначенный проверяющий или руководитель проекта), выпуск, задачи пользователя и проекта,
  отмена задач, сводка, кандидаты в проверяющие; доступные действия вычисляются сервером; аудит каждого решения.
* Desktop: блок «Согласование» в карточке документа (действия, открытые задачи, история решений), страница «Задачи» (мои согласования с решением из списка, задачи на доработку), сводка на главной,
  диалоги отправки на проверку и решения.
* Тесты: 171 модульный и 71 интеграционный; полный цикл «загрузка → проверка → возврат с замечаниями → новая версия → проверка → согласование → выпуск → новая версия после выпуска».

## Этап 5 — что сделано

* Эксплуатация сервера: режим обратного прокси с доверенными адресами, проверка записи в хранилище в `/health/ready`, команда `--verify-storage`, структурированные логи (JSON по настройке).
* Безопасность: временные пароли с обязательной сменой (сервер и Desktop), тест отсутствия секретов в журнале сервера, документированная ротация ключей агентов.
* Журналы: файловый журнал Desktop и агента с ротацией, журнал событий Windows для службы агента.
* Надёжность (автотесты на реальной базе): перезапуск сервера под нагрузкой агента без дубликатов версий, повтор загрузки после падения агента, истечение токенов пользователя и агента посреди сеанса,
  потоковая загрузка 8 МиБ без известной длины, два агента в один документ, отказ хранилища при чтении/записи, недоступность хранилища в `/health/ready`.
* Резервное копирование: `scripts/backup.sh`, `scripts/restore.sh`, учения на dev-кластере с проверкой состояния и `--verify-storage`.
* Документация: чек-лист первичной настройки, публикация релиза, `windows-verification.md`.
* Итог: 171 модульный и 81 интеграционный тест.

## Этапы 1–5 — что требует внимания

1. **Визуальная проверка Desktop на Windows** — на машине разработки (macOS) WPF только компилируется. Нужен прогон: вход, переключение организации, все страницы и диалоги.
2. **Репозиторий Git** — каталог проекта находится внутри репозитория домашнего каталога; рекомендуется инициализировать отдельный репозиторий `drawingflow` (решение за владельцем).
3. **TLS-сертификат** и адрес сервера для пилота.
4. Файловый журнал Desktop и `ForwardedHeaders` на сервере за обратным прокси — этап 5.

## Перед пилотом

1. Выполнить `windows-verification.md` на Windows 10/11 (Desktop, установка службы агента, сетевые папки, DPAPI).
2. Развернуть сервер с TLS-сертификатом организации и PostgreSQL по `installation.md`; пройти чек-лист первичной настройки.
3. Настроить расписание `backup.sh` и проверить восстановление на стенде организации.

## После пилота (кандидаты)

* Параллельное согласование несколькими проверяющими (кворум), уведомления о задачах.
* Возобновляемая многочастная загрузка больших файлов.
* S3-совместимое хранилище, антивирусная проверка в конвейере загрузки.
* Сравнение содержимого PDF/изображений, интеграции с CAD/BIM.
* Настройка папок наблюдения инженерами в Desktop (сейчас — через администраторов организации).
