# Резервное копирование и восстановление

## 1. Что защищаем

| Данные | Где | Способ |
|---|---|---|
| Метаданные, пользователи, проекты, документы и версии, согласования, агенты, аудит | PostgreSQL `drawingflow` | `pg_dump -Fc` ежедневно; WAL-архив при требованиях RPO < 24 ч |
| Содержимое версий документов | Каталог хранилища `Storage:RootPath` | Файловое копирование (rsync/robocopy) или снимок тома; объекты неизменяемы — достаточно инкрементальной копии |
| Конфигурация и секреты | `appsettings.Production.json`, файл переменных окружения, PFX-сертификат | Защищённое хранилище секретов организации |
| Локальные очереди агентов | `%ProgramData%\DrawingFlow\Agent\queue.db` на рабочих станциях | Не копируются: после потери агент заново обнаружит файлы сверкой; ключ агента перевыпускается |

Порядок согласованности: сначала копия файлов хранилища, затем `pg_dump`. Версия без файла хуже файла без версии: после восстановления
`DrawingFlow.Server --verify-storage` перечисляет версии без объектов, а «лишние» файлы безвредны.

## 2. Скрипты

* `scripts/backup.sh [каталог]` — дамп базы (`drawingflow.dump`, формат custom), архив хранилища (`storage.tar.gz`, без `.tmp`), манифест с количеством документов/версий и SHA-256 дампа.
* `scripts/restore.sh <каталог> --yes` — проверка контрольной суммы дампа, пересоздание базы, `pg_restore`, замена каталога хранилища. Сервер должен быть остановлен.
* `DrawingFlow.Server --verify-storage` — сверка всех `DocumentVersions.StorageKey` с объектами хранилища (только чтение); код выхода 0 — всё на месте, 3 — есть отсутствующие объекты, список выводится.

Параметры подключения — переменные `DF_PGHOST`, `DF_PGPORT`, `DF_PGUSER`, `DF_PGPASSWORD`, `DF_PGDATABASE`, `DF_STORAGE`, `PG_BIN`
(по умолчанию — dev-кластер `scripts/dev-postgres.sh`). В эксплуатации запускайте скрипты от учётной записи с правами на базу и каталог хранилища, копии шифруйте и выносите на другой носитель.

## 3. Регламент

* Ежедневно: `backup.sh` по расписанию; хранить не менее 14 ежедневных и 3 месячных копий.
* Еженедельно: `pg_restore --list` копии (читаемость), сравнение `versions=` в манифесте с ростом данных.
* Ежеквартально: полный прогон восстановления на тестовом стенде (раздел 5).
* При требовании RPO менее суток: `archive_mode = on` и архивирование WAL (`pgBackRest` или `wal-g`).

## 4. Восстановление

1. Остановите службу сервера (агенты и Desktop будут повторять запросы автоматически).
2. `scripts/restore.sh <каталог_копии> --yes` (или вручную: `createdb`, `pg_restore --no-owner`, распаковка хранилища в `Storage:RootPath`).
3. Если версия приложения новее копии — `DrawingFlow.Server --migrate`.
4. `DrawingFlow.Server --verify-storage`; при отсутствующих объектах — восстановить файлы из более свежей файловой копии или попросить инженеров загрузить версии заново (агенты сделают это автоматически при наличии файлов в папках наблюдения).
5. Запустите службу; проверьте `/health/ready`, вход, открытие проекта и скачивание версии.
6. Сессии пользователей и токены агентов остаются действительными, если `Jwt:SigningKey` не менялся. Операции агентов, завершённые после момента копии, будут выполнены повторно: ключи идемпотентности в их локальных очередях гарантируют отсутствие дубликатов.

## 5. Учения (выполнены 17.10.2026 на dev-кластере)

Сценарий: создан документ с версией → `backup.sh` → добавлены версия и документ → `restore.sh --yes` → состояние вернулось к моменту копии
(количество документов и версий совпало с манифестом), `--verify-storage` сообщил об отсутствии расхождений (код 0). После намеренного удаления одного файла
хранилища `--verify-storage` вывел документ, номер версии и ключ объекта и завершился кодом 3; после возврата файла — снова 0.

## 6. Сценарии отказа

| Сценарий | Действия |
|---|---|
| Повреждение БД | Восстановление из последнего дампа + WAL; `--verify-storage` для сверки с хранилищем |
| Потеря хранилища файлов | Восстановление файлов из копии; отсутствующие версии видны в отчёте `--verify-storage`; пользователям предлагается повторная загрузка (агенты сделают это сами) |
| Утечка ключа подписи JWT | Сменить `Jwt:SigningKey` (все сессии и токены агентов станут недействительными; агенты получат новые токены по своим ключам установки), проверить журнал аудита |
| Утечка ключа агента | Отозвать ключ в Desktop («Агенты» → «Отозвать ключ»), зарегистрировать агента заново |
| Отзыв сертификата TLS | Заменить PFX, перезапустить службу |
| Потеря рабочей станции с агентом | Отозвать её ключ; на новой станции зарегистрировать агента и настроить папки заново |
