# Безопасность

## 1. Транспорт

* Клиент ↔ сервер — только HTTPS в эксплуатации. Desktop отказывается подключаться по `http://` к любому адресу, кроме loopback (локальная разработка).
* Kestrel настраивается сертификатом организации (`Kestrel:Endpoints:Https`), либо сервер размещается за обратным прокси с TLS. Пример — в `installation.md`.
* PostgreSQL слушает только внутренний интерфейс; клиенты и агенты **никогда** не подключаются к БД напрямую.
* Каталог файлового хранилища (`Storage:RootPath`) не публикуется HTTP-сервером как статика; выдача файлов — только через авторизованную конечную точку скачивания.
  Права на каталог — только у учётной записи службы сервера.

## 2. Аутентификация

| Механизм | Реализация |
|---|---|
| Пароли | PBKDF2-HMAC-SHA512 (ASP.NET Core Identity `PasswordHasher`, формат V3), при входе выполняется перехеширование при смене параметров |
| Требования к паролю | ≥ 8 символов, буквы и цифры (`Guard.Password`); проверяется на сервере, подсказка — на клиенте |
| Access-токен | JWT HS256, 60 минут (настраивается), ключ ≥ 32 символов из конфигурации; проверка издателя, аудитории, подписи и срока |
| Refresh-токен | 256 бит случайных данных, в БД только SHA-256; ротация при каждом обновлении; повторное предъявление обменянного токена отзывает все сессии пользователя |
| Выход | Отзыв refresh-токена; идемпотентен |
| Смена пароля | Требует текущий пароль, отзывает все прочие сессии, возвращает новую |
| Блокировка пользователя | `IsActive = false` — отзыв всех refresh-токенов, запрет входа и обновления |
| Подбор пароля | Ограничение частоты `/api/auth/login`, `/api/auth/refresh` и `/api/agents/token` по адресу клиента (по умолчанию 20/мин), ответ 429 |
| Временные пароли | Первичный администратор (`Bootstrap:Administrator:MustChangePassword`, по умолчанию `true`) и пользователи, созданные с флагом `RequirePasswordChange` (по умолчанию), до смены пароля получают 403 `password_change_required` на все вызовы, кроме смены пароля, продления сессии, профиля и выхода; Desktop показывает обязательный диалог смены пароля |
| Утечка информации | Для неизвестного логина и неверного пароля — одинаковое сообщение; хеш проверяется даже для неизвестного логина (выравнивание времени ответа) |

За обратным прокси включите `ReverseProxy:Enabled` и перечислите адреса прокси в `ReverseProxy:KnownProxies`/`KnownNetworks`: тогда ограничение частоты и адрес клиента в аудите берутся из `X-Forwarded-For`
(с пустыми списками заголовку доверяется от любого отправителя — сервер пишет предупреждение при старте).

## 3. Авторизация

* Проверка прав — **только на сервере** (`AccessService`, `AccessRules`). UI скрывает недоступные действия, но это не мера безопасности.
* Политика по умолчанию — «только аутентифицированные»; анонимны лишь `/api/auth/*`, `/api/server/info`, `/health/*`.
* Межорганизационный и межпроектный доступ запрещён; попытки доступа к чужим объектам получают 404 (не раскрывается существование объекта).
* Повышение привилегий: администратор организации не может назначать и снимать владельцев; назначать администраторов сервера может только администратор сервера;
  владелец не может лишить организацию последнего владельца.
* Пользователь может быть добавлен в проект, только если он уже состоит в организации.
* Согласование: отправить на проверку — `SubmitForReview` (инженер и выше); решение — `Review`, причём только назначенный проверяющий или руководитель проекта;
  выпуск — `Release` (руководитель проекта). Отменить задачу может её создатель или руководитель проекта. Все решения записываются в аудит с комментариями.

Покрытие тестами: `AuthorizationTests` (изоляция, IDOR, матрица ролей), `OrganizationAndProjectTests` (правила членства), `HealthAndAuthTests` (токены, блокировки, ограничение частоты),
`DocumentTests` (доступ к документам и скачиванию, идемпотентность, конкурентная выдача номеров, лимит размера, отказ хранилища),
`AgentApiTests` (границы прав агента, отзыв, папки, очередь), `AgentPipelineTests` (ровно одна версия на стабильное изменение, повторы, перезапуск, обрыв сети, отзыв),
`WorkflowTests` (полный цикл согласования и выпуска, права проверяющего/руководителя, обязательный комментарий, сброс согласования новой версией),
`SecurityHardeningTests` (временный пароль, отсутствие секретов в журнале, доверие заголовкам прокси только в режиме прокси, отсутствие внутренних деталей в ошибках),
`ReliabilityTests` (перезапуск сервера под нагрузкой агента, истечение токенов пользователя и агента посреди сеанса, большой файл потоком, два агента в один документ, готовность хранилища и сверка объектов).

## 4. Валидация входных данных

* Доменные проверки с русскими сообщениями (`Guard`): длины, допустимые символы кодов и логинов, формат e-mail.
* Ошибки привязки модели и некорректный JSON возвращаются как 400 без внутренних деталей сериализатора.
* Размер страницы ограничен 200 записями.
* Файлы: лимит размера (`Storage:MaxFileSizeBytes`, проверяется при потоковой записи; Kestrel ограничивает тело запроса тем же пределом), проверка SHA-256
  (несовпадение с заявленным хешем — отказ и удаление файла), внутренние ключи хранения `yyyy/MM/{документ}/{версия}` вместо пользовательских имён и путей,
  проверка ключей и запрет выхода за корневой каталог хранилища, расширение файла сохраняется только из латинских букв и цифр.
* Имена файлов: отбрасываются каталоги, запрещены управляющие и спецсимволы; при скачивании имя передаётся в `Content-Disposition` в кодировке UTF-8.

## 5. Аудит и журналирование

* Журнал аудита (`AuditEvents`) — только добавление; фиксируются вход/неудачный вход/выход, создание пользователей и организаций, изменения проектов и ролей,
  регистрация документов, загрузка и скачивание версий, архивирование, отправка на проверку, согласование, возврат на доработку, выпуск, отмена задач,
  регистрация/отзыв агентов, изменения папок наблюдения, решения по операциям синхронизации.
  Действия агента записываются с `ActorAgentId` и именем «Агент: …». В `Details` не попадают пароли, токены и ключи.
* Логи сервера — структурированные (`Microsoft.Extensions.Logging`; в production рекомендован JSON-форматтер консоли или системный журнал). Секреты не логируются:
  интеграционный тест `Server_logs_never_contain_secrets` перехватывает журнал сервера и проверяет отсутствие паролей, токенов и ключей агентов после сценариев входа, регистрации агента и загрузки.
* Журналы Desktop (`%LOCALAPPDATA%\DrawingFlow\logs`) и агента (`%ProgramData%\DrawingFlow\Agent\logs`, журнал событий Windows) содержат только сообщения приложения без учётных данных.
* Каждый ответ об ошибке содержит `traceId` для сопоставления с журналом сервера.

## 6. Секреты и конфигурация

* Секреты (`Jwt:SigningKey`, строка подключения, пароль первичного администратора) задаются переменными окружения или защищённым файлом конфигурации, не хранятся в репозитории.
  Значения в `appsettings.Development.json` предназначены только для локальной разработки.
* Первичный администратор создаётся один раз при пустой базе; после первого входа пароль следует сменить, а переменные `Bootstrap__*` удалить.
* Миграции в production выполняются явно (`--migrate`), не автоматически.

## 7. Рабочая станция

* Сессия Desktop хранится в `%LOCALAPPDATA%\DrawingFlow\session.bin`, зашифрованной DPAPI в области текущего пользователя Windows; при выключении опции «запомнить меня» файл удаляется.
* Пароль в памяти очищается после входа; в настройках и журналах не сохраняется.
* Агент получает индивидуальный ключ установки (256 бит), который показывается администратору один раз; на сервере хранится SHA-256.
  На рабочей станции ключ зашифрован DPAPI в области компьютера (`%ProgramData%\DrawingFlow\Agent\agent.credential`); вне Windows — файл с правами 0600 (только разработка).
* Агент обменивает ключ на JWT со сроком 60 минут (`principal_type = agent`); права — только `View` и `UploadVersions` в проектах с включёнными папками наблюдения
  (и `RegisterDocuments` при включённой автоматической регистрации). Пользовательские конечные точки агенту недоступны (403).
* Отзыв ключа действует немедленно: каждый запрос агента проверяется по базе, папки отключаются; агент приостанавливает работу, сохраняя очередь.
* Срок жизни ключа агента не ограничен; рекомендуемая ротация — при смене ответственного за рабочую станцию или раз в год: зарегистрировать агента заново и отозвать старый ключ.
  Токен агента живёт `Jwt:AccessTokenLifetimeMinutes` (60 минут) и продлевается ключом автоматически.

## 8. Точки расширения

* Антивирусная проверка загружаемых файлов — место в конвейере после записи во временный файл и до регистрации версии (`DocumentService.UploadVersionAsync`); реализация отсутствует.
* Внешние поставщики удостоверений (AD/LDAP, OIDC) — замена `AuthService.LoginAsync` без изменения модели токенов.
