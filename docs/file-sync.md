# Синхронизация файлов (DrawingFlow.Agent)

**Статус: реализовано на этапе 3.** Документ описывает фактическое поведение службы `DrawingFlow.Agent` и серверной части.

## 1. Принципы

1. `FileSystemWatcher` — лишь источник подсказок; истина — периодическая сверка (reconciliation) содержимого папок с локальной очередью и известными состояниями файлов (`FileStates`).
2. Файл не загружается, пока пишется: размер и время изменения должны не меняться в течение окна стабильности (`Agent:StabilityWindow`, по умолчанию 5 с), файл должен открываться на чтение.
3. Содержимое идентифицируется SHA-256. Совпадение хеша с уже загруженной версией («только изменилось время файла») не создаёт новую версию.
4. Удаление файла в папке **не удаляет** документ и версии на сервере; операция переходит в состояние «Отменена (файл исчез)». Агент не перемещает, не переименовывает и не удаляет рабочие файлы.
5. Операция завершена только после ответа сервера с версией, чей хеш совпадает с локальным.
6. Идентификатор локальной операции — ключ идемпотентности загрузки: повтор после обрыва связи или перезапуска не создаёт дубликатов версии.

## 2. Компоненты агента

| Компонент | Файл | Назначение |
|---|---|---|
| `AgentHostedService` | `Hosting/AgentHostedService.cs` | Главный цикл: восстановление очереди, конфигурация, наблюдение, обработка, отчёты, сердцебиение, сверка, очистка |
| `SyncEngine` | `Sync/SyncEngine.cs` | Конвейер операций; все шаги — явные методы (`ReconcileAsync`, `ProcessDueAsync`, `ReportAsync`, `HeartbeatAsync`), что позволяет тестировать без таймеров |
| `SyncQueue` + `AgentQueueDbContext` | `Queue/` | Устойчивая очередь SQLite: операции, состояния файлов, настройки (кэш конфигурации) |
| `FolderWatcherHost` | `Watching/FolderWatcherHost.cs` | Наблюдатели по включённым папкам, дебаунс событий (`Agent:DebounceDelay`) |
| `FileMatcher`, `RetryPolicy` | `Sync/` | Маски файлов, извлечение номера документа, экспоненциальные повторы |
| `AgentCredentialStore` | `Security/` | Ключ установки: DPAPI (область компьютера) на Windows, файл 0600 в режиме разработки |
| `AgentTokenHandler` | `DrawingFlow.Client` | Обмен ключа на короткоживущий токен, упреждающее продление, обнаружение отзыва |

## 3. Конвейер обработки операции

```
обнаружение (событие после дебаунса или сверка) → кандидат в очереди (не более одной активной операции на путь)
→ ожидание стабильности (размер/время не меняются StabilityWindow; файл открывается на чтение; занятый файл → повтор с задержкой)
→ Processing → SHA-256 потоково → если хеш равен последней загруженной версии файла → Completed без загрузки
→ сопоставление: правило папки → номер документа → GET /api/projects/{id}/documents/lookup
     1 документ → загрузка; несколько → NeedsResolution (кандидаты сохраняются); 0 → AutoRegisterUnknown ? регистрация документа : NeedsResolution
→ POST /api/documents/{id}/versions (поток файла, idempotencyKey = Id операции, sha256Hash)
→ сверка хеша в ответе → FileState обновлён → Completed
```

Ошибки и повторы (`Agent:MaxRetries`, `InitialRetryDelay`, `MaxRetryDelay`): нет связи/5xx/503 — повтор с удвоением задержки; исчерпание попыток — `Failed` (пользователь может запросить повтор);
400 (файл изменился во время передачи) — наблюдение стабильности заново; 404/409/422 (документ не найден, конфликт, архив) — `NeedsResolution`;
413 — `Failed`; 401/403 при отозванном ключе — обработка приостанавливается, очередь сохраняется.

## 4. Локальная очередь (SQLite, `queue.db` в каталоге данных)

* `SyncOperations`: Id (ключ идемпотентности), WatchedFolderId, ProjectId, FilePath, FileName, DetectedAtUtc, LastObservedSize/ModifiedAtUtc/AtUtc, Sha256, Status, RetryCount, NextAttemptAtUtc, LastError, DocumentId, DocumentVersionId, CandidatesJson, UpdatedAtUtc, CompletedAtUtc, ReportPending.
* `FileStates`: FilePath, WatchedFolderId, Sha256, Size, ModifiedAtUtc, DocumentId, DocumentVersionId.
* `Settings`: версия схемы, кэш конфигурации (для старта без связи с сервером).

Состояния: `Pending → Processing → Completed | Failed | NeedsResolution | Cancelled`; `Dismissed` ставит пользователь. После перезапуска операции `Processing` возвращаются в `Pending`.
Завершённые операции удаляются через `Agent:CompletedRetention` (30 дней).

## 5. Сопоставление файла с документом

| Правило | Поведение |
|---|---|
| `NumberFromFileName` (по умолчанию) | Номер извлекается регулярным выражением с группой `number`; по умолчанию `^(?<number>[^\s_]+)` — часть имени до первого пробела или подчёркивания (`АР-01_план.dwg` → `АР-01`) |
| `FileNameIsNumber` | Имя файла без расширения — номер документа |
| `VersionFileName` | Совпадение с именем файла текущей версии документа |

Неизвестный файл не создаёт документ, если для папки не включено `AutoRegisterUnknown`; неоднозначность всегда ждёт решения пользователя (Desktop → «Синхронизация» → «Сопоставить»).
Всегда исключаются временные и служебные файлы (`~$*`, `*.tmp`, `*.bak`, `*.part`, `*.dwl`, `*.dwl2`, `Thumbs.db`, …) и скрытые файлы; дополнительно — маски исключения папки и `Agent:ExcludedRoots`.

## 6. Взаимодействие с сервером

| Вызов | Назначение |
|---|---|
| `POST /api/agents/token` | Обмен ключа установки на токен (60 мин); ограничение частоты как у входа |
| `GET /api/agent/configuration` | Папки наблюдения агента (кэшируются локально) |
| `POST /api/agent/heartbeat` | Состояние агента и счётчики очереди; затем `GET /api/agent/operations/actions` |
| `PUT /api/agent/operations` | Пакет отчётов об операциях; в ответе — действия пользователей (повтор, загрузка в выбранный документ, отклонение) |
| `GET /api/projects/{id}/documents/lookup` | Поиск документа по номеру/имени файла |
| `POST /api/documents/{id}/versions` | Загрузка версии от имени агента (`CreatedByAgentId`) |

Права агента на сервере: только проекты с включёнными папками наблюдения; `View` и `UploadVersions`, `RegisterDocuments` — лишь при `AutoRegisterUnknown`.
Отзыв ключа действует немедленно (проверка на каждом запросе), папки агента отключаются.

## 7. Предотвращение циклов

Desktop скачивает версии в `%LOCALAPPDATA%\DrawingFlow\cache`, а не в рабочие папки; этот и другие каталоги можно явно исключить через `Agent:ExcludedRoots`
(например, корень хранилища сервера, если агент установлен на той же машине). Повторная загрузка файла с уже известным хешем не создаёт версию.

## 8. Что видит Desktop

«Агенты»: состояние связи (сердцебиение не старше 3 минут), счётчики очереди, папки наблюдения; «Синхронизация»: операции всех агентов организации
(для инженеров — по их проектам) с действиями «Повторить», «Сопоставить», «Отклонить»; на главной — сводка.

## 9. Ограничения

* Наблюдатель файловой системы не тестируется автоматически (зависит от ОС); покрытие — через сверку и ручную проверку.
* Нет возобновляемой многочастной загрузки: повтор начинает передачу файла заново.
* Схема локальной очереди создаётся `EnsureCreated`; при смене версии схемы база пересоздаётся, незавершённые операции обнаруживаются сверкой заново.
